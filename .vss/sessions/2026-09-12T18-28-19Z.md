## Rulings I made
- **Item 30, `--now-source` on the checks_27 quota-wait test.** Accepted the writer's deviation and refused the fallback instruction to shorten the 5000 s target. Verified myself: the whole test function runs in 0.22 s, because the 5000 s `resetsAt` is a target the test never waits out - it guarantees the supervisor is parked in the quota wait when `stop` arrives. Shortening it would let the wait finish first and the assertion would pass vacuously. The hazard the item names is closed by `_communicate_or_kill` on all four call sites. Cost if wrong: that path stays on the real clock, so a future change to the supervisor's sleep could make it slow with nothing catching it early. Logged as an open TODO item.
- **Item 5, which host-onboarding calls stay fatal.** `git-check`, `source-check` and `check` stay `|| return 1` because they gate a `git init` and a credential mount; `take-agent`, `memory-get`, `memory-set` and `cancel-agent` degrade through `_vibe_onboard_soft`. Cost if wrong: a genuinely broken host state becomes a warning rather than a stop, for runtime memory only.
- **Item 10, how to reach `--new-run`.** Implemented as an explicit launcher flag rather than making `--codex-run` imply it, so the launcher never duplicates the supervisor's complete/mismatched state semantics. Cost if wrong: one more flag to learn.
- **Item 9, Claude-only flags under a Codex lead.** Refused loudly rather than silently dropped, for ANY Codex lead including one that came from the folder's remembered runtime. Cost if wrong: someone with a codex-remembered folder who types `--continue` now gets an error instead of a Claude session.
- **Item 1, the ancestor predicate.** The first pass turned the refusal into an AND and so began accepting a 0755 directory owned by another user and a root-owned 0777 non-sticky one. Sent back as fix round 1/5 and narrowed: ours is always safe, another non-root owner is always unsafe, root-owned is unsafe only without the sticky bit. Cost if wrong: none identified - this is strictly narrower than both the original and the first attempt.
- **Item 6, containerEnv vs remoteEnv.** Mirrored `DISABLE_AUTOUPDATER` into both, matching the file's existing convention for its five non-secret variables, rather than relying on containerEnv alone. Cost if wrong: one redundant env entry.
- **Commit gating.** Held all commits until every writer had landed and one full `smoke-test.py` run was green, rather than gating per wave. Five writers were editing the tree concurrently, so a per-wave full-suite run would have been meaningless. `smoke/runner.py` is committed LAST so every intermediate tree stays green - an unwired test is inert. Cost if wrong: a bad group is only isolated at the end rather than per wave.
- **Scope extensions accepted.** Wave 0's extra bare-assert conversion in checks_33 and its `sys.path` fixes for two standalone entry points; the Task&I writer's note that `guardedTransport`'s origin branch is structurally unreachable via the legitimate config path, so its test drives the fixed classification through a custom `PREDISPATCH`-tagged transport instead.
