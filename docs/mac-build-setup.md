# Let Vibe set up native Mac builds

Tell the agent: **“Set up native builds using Vibe's Mac setup guide. Do everything you can, and give me only the next step that needs my Mac.”**

This is optional. Web, Python, Node and other container-supported work can start immediately. Native Apple builds need Xcode and the dedicated `claude` Mac account. That account limits access to your personal files; builds still have that account's privileges.

The assisting agent owns setup. Do not send the user the protocol document as homework. Work through these three stages and expose only the next necessary user action:

1. **Check what already exists.** Inspect this project's local bridge configuration and public connection metadata without displaying private keys. Reuse an authorised working connection, run `mac-build doctor`, and diagnose its result. If the container lacks a connection, report that fact; do not search unrelated projects for keys. Ask the user to open a host-side coding session in the same project only when host access is needed. An approved container session cannot grant itself Mac administrator access.
2. **Prepare and install.** The host-side agent prepares the exact reviewed runner, configuration, fixed build/test wrappers, and a dedicated project key following [the installation reference](mac-build-protocol.md#host-installation-administrator-only). Determine this project's actual build command; do not assume Swift Package Manager for an Xcode project. Stage a reviewable install plan before any privileged write. Run authorised host steps when available; ask the user only for the local administrator confirmation or action the agent cannot perform. Preserve existing keys and installations. Obtain the host-key fingerprint from the Mac itself and verify it before pinning; network key discovery alone is not verification. No private key or password belongs in chat. There is currently no one-command host installer: the agent must prepare machine-specific commands, not invent an installer command.
3. **Prove it works.** The agent runs `mac-build doctor`, then a small real build and relevant test using the project's explicit source roots. Report the snapshot fingerprint, test result and artifact paths. Check simulator availability separately if needed. A screenshot counts as evidence of this change only when the configured pipeline built, installed and launched that same snapshot. On uncertain completion, retain the request and reconcile before replay; do not issue a fresh job as a retry.

If the user must act, show one short command or UI action and what success looks like, then continue independent development. Keep technical installation and recovery details in the reference. Setup is complete only after the live checks pass; fixtures cannot verify the Mac installation.
