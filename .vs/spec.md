# Spec — task_038: `--aux` model slot — a second, cheaper or greener model for mechanical jobs only

## Task summary
Martin's queue item 4 (2026-09-04): plug in a second model — a local Ollama/LM Studio model on the Mac or a LAN box, GreenPT, or any OpenAI-compatible endpoint — for mechanical jobs only, never replacing Claude Code's own model (that would break the subscription-only invariant and Anthropic's consumer terms). Two consumers: `/learn` embeddings (semantic dedupe/review) and an optional extra reviewer rung in `/vs` (`--aux-review`) that runs on the aux model and feeds the chair a third opinion. Zero spend by default: nothing runs unless `~/.vibe/aux` or `--aux <url>` names an endpoint. Carbon: when the provider returns a per-request impact field (GreenPT does), surface it in the run's cost line. Firewall: LAN hosts and `host.docker.internal` are reachable today; `api.greenpt.ai` is NOT allowlisted — adding it is a firewall edit and therefore Martin's separate call (named as a follow-up, not done here). Replaces the older GreenPT TODO items. Status at this commit: awaiting Martin's approval (`/vs --spec-first`).

## Acceptance criteria
- AC1 Launcher: `vibe --aux <url>` and a config file `~/.vibe/aux` (one line: the base URL; optional second line `model=<name>`; optional `key=<token>` line for endpoints that need one; file created `chmod 600`) export `VIBE_AUX_URL`, `VIBE_AUX_MODEL`, `VIBE_AUX_KEY` at TOP level of the launcher (never inside `_build_override_config`'s subshell) and pass them through `remoteEnv` as `${localEnv:NAME}` — never `containerEnv` (which bakes the literal into the rendered file on disk) — exactly as `GITHUB_TOKEN` is passed today; absent both → the three `remoteEnv` entries are still present as `${localEnv:...}` placeholders (empty in the container) so the rendered override is byte-identical whether or not aux is configured (smoke: render with and without the fixture config and diff). The launcher refuses `~/.vibe/aux` unless its mode is 600 and it is owned by the user (one stderr line naming `chmod 600 ~/.vibe/aux`) — a NEW read-side check modelled on how `~/.vibe/tokens` is written (600 at write time; nothing refuses a loosened tokens file today), using the launcher's existing BSD/GNU `stat -f`/`stat -c` fork for mode and owner.
- AC2 Container helper `/usr/local/bin/vibe-aux` (bash, curl only, no new deps): `vibe-aux embed <text>` calls `${VIBE_AUX_URL}/v1/embeddings` and prints the vector as JSON; `vibe-aux chat <system> <user>` calls `/v1/chat/completions` and prints the assistant text; both send `Authorization: Bearer $VIBE_AUX_KEY` only when set and only to `$VIBE_AUX_URL`; both exit 2 with one stderr line when `VIBE_AUX_URL` is unset; both surface a provider `impact`/carbon field on stderr as `aux impact: <json>` when present; 20 s timeout; the key never appears in argv (curl config on stdin) or logs.
- AC3 Firewall: no change to `init-firewall.sh`. The spec states that a cloud aux host needs Martin to allowlist it, and `vibe --aux` prints a one-line warning at launch when the URL's host is neither RFC1918/loopback/`host.docker.internal` nor already allowlisted (checked by the launcher against the domain list in `init-firewall.sh`, read from the file at launch — with a smoke test that the launcher's parser and the firewall's list agree, so they cannot drift).
- AC4 `/vs --aux-review`: harness prose in `vs.md` — an extra Reviewer rung run via `vibe-aux chat` on the spec + `diff.patch`, output to `.vs/cycle-N/aux-review.md`, read by the Evaluator as ONE more, explicitly low-confidence input (a local 7–30B model is far below Sonnet for judgment; never a gate; the mechanical Tester still governs); a `Model plan` line `Aux: <model>@<host>` when active; documented as opt-in and orthogonal to `--panel`.
- AC5 `/learn`: when the aux slot is configured, the semantic check embeds the NEW entry and every existing entry on each run (the library is small — tens of entries — so no index is needed; re-embedding is the design, stated honestly; the first non-zero exit from `vibe-aux` aborts the whole re-embed and falls back at once, so a hanging endpoint costs one 20 s timeout, not one per entry) and reports the nearest existing entry by cosine similarity above 0.85 as a possible duplicate, alongside today's text scan; when unconfigured, unchanged; documented in `learn.md`; no change to the write-confirm hook.
- AC5b Degrade silently: if the endpoint is configured but unreachable or returns non-JSON, `vibe-aux` exits 3 with one stderr line, `/learn` falls back to the text scan and says so in one line, and `/vs --aux-review` writes `aux-review.md` containing `aux unavailable` and the cycle proceeds without it — never a cycle fail, never a hang (the 20 s timeout).
- AC6 Smoke tests: a python `http.server` fixture serving `/v1/embeddings` and `/v1/chat/completions` (recording the Authorization header and the body); tests for AC1 (override rendering with/without config), AC2 (both subcommands, bearer only to the configured URL, exit 2 unset, impact line surfaced, key never in argv — verified with a stubbed `curl` on PATH that records its argv and its stdin config: the bearer must appear only in the stdin config), AC3 (warning fires for a non-LAN, non-allowlisted host; silent for `http://host.docker.internal:11434`); all env via `_isolate_extras_env`, stdin=DEVNULL.
- AC7 Docs: README section "Second model (aux)" — what it is for, what it never does, the Ollama-on-the-Mac recipe (`OLLAMA_HOST=0.0.0.0` on the Mac, URL `http://host.docker.internal:11434`), GreenPT needs the allowlist; CLAUDE.md § Non-goals gains one sentence: configuring `~/.vibe/aux` or passing `--aux` IS the consent act (no default endpoint ever exists) and aux never replaces Claude Code's model; CHANGELOG.
- AC8 `python3 code-check.py` and `python3 smoke-test.py < /dev/null` exit 0; the launcher change is additive and `uname`-independent; `MANUAL-TESTS.md` gets one Mac-side test (Ollama recipe end-to-end).
