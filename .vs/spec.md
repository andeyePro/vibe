## Shape (binding)
- A profile is a thin child image: `devcontainer/profiles/<name>/Dockerfile` opens `ARG BASE=vibe-dev:latest` then `FROM ${BASE}`, adds ONE `RUN` layer (toolchain only, never project deps). The launcher builds it AFTER the base is current: `docker build --build-arg BASE="$BASE_TAG" -t "vibe-dev:<name>" "$DEVCONTAINER_DIR/profiles/<name>"`.
- `devcontainer/Dockerfile` is untouched. Base tag stays `vibe-dev:latest`; base marker stays `~/.vibe/.image-built`. The base-staleness `find` over `$DEVCONTAINER_DIR` must prune `profiles/` (a profile edit must never rebuild the base for everyone).
- Profile marker: `~/.vibe/.image-built-<name>`. Profile stale ⇔ any file under `profiles/<name>` newer than its marker, OR the base was (re)built this launch, OR `--rebuild`.
- Selection precedence, first hit wins: `--profile <name>` flag → `.vibe/profile` (first line, trimmed; already gitignored under `.vibe/`) → `VIBE_PROFILE` from `~/.vibe/config` → none. `--profile none` = base, and suppresses the suggestion below. Custom profiles: `~/.vibe/profiles/<name>/Dockerfile`, resolved after the shipped set. Unknown name → exit 1 listing available names (shipped + custom), never a silent fall-through.
- Suggestion, not auto-detect: if no profile is selected and the workspace has `pyproject.toml` or `requirements.txt`, print ONE stderr line `  ◆ python project? vibe --profile python adds the toolchain (once per project; --profile none silences)` once per machine per project (marker `~/.vibe/.profile-hint-<sha1 of workspace path>`).
- `devcontainer.json` keeps `"image": "vibe-dev:latest"`; `render_devcontainer_with_mounts` sets `cfg["image"]` from env `VIBE_IMAGE_TAG` when non-empty (same pattern as `VIBE_OP_ADDHOST`), else leaves the file's value.
- Drift: `image_drift_needs_recreate "$WORKSPACE" "$IMAGE_TAG"` is already called with the resolved tag; switching profile therefore recreates the container. The launch header prints `  ◆ profile: <name> (vibe-dev:<name>)` when profiled; nothing when not.
- `python` profile: `python3.12`-class interpreter via the Debian image's apt (whatever `python3` the base's Debian provides — do not pin a minor), `pipx`, `uv`, `ruff`, `mypy` — installed in ONE `RUN` with `apt-get install --no-install-recommends` + `rm -rf /var/lib/apt/lists/*`; tools on PATH for user `node`. No firewall change: installs happen at build time, before `init-firewall.sh` runs.
