# task_050 — Codex panel runner for `/vs --panel` (plan item 8, branch `astra`)

## Task summary

`/vs --panel N` fans the review role out to N blind panellists (`vs.md` § Step 5c). Under Codex, `multi_agent` is pinned off (task_046) and native subagents are not blind anyway (openai/codex#26130 open, `fork_turns` defaults to a full parent fork), so the panel must be N separate top-level processes. This task ships `devcontainer/codex-panel.mjs` (installed as `/usr/local/bin/codex-panel`): it runs N independent `codex exec` reviewers exactly as `vibe-delegate review codex` runs one, each in its own private temp cwd, each fed the same diff snapshot on stdin plus its own nonce, all tools disabled, `--ephemeral`, and collects N JSON verdicts for the chair. Isolation is the process boundary plus the tool-less configuration (plan D6): a reviewer can read nothing but its stdin. The TODO mandate's "distinct Codex homes" cannot be delivered without copying `auth.json` (D6), so the shared `$CODEX_HOME` is accepted and stated: in `--verify` mode (no `--ephemeral`) each reviewer's rollout, containing the full diff and its nonce, is written to the user's real `~/.codex/sessions/` and stays there until the user deletes it — verify runs are therefore Martin-gated (N live Astra calls) and meant for throwaway diffs only. What ships is the argv contract, the ordered verify/ship pin, the nonce plumbing, the rollout-path contract pinned from source, and the collection logic, all against a stub.

Rollout path contract at tag `rust-v0.154.0` (`rollout/src/rollout_file_name.rs:67-70`, `rollout/src/recorder.rs:1646-1647`, `rollout/src/compression.rs`): `$CODEX_HOME/sessions/<YYYY>/<MM>/<DD>/rollout-<YYYY-MM-DDTHH-MM-SS>-<thread_id>.jsonl`, or `rollout-<timestamp>-<thread_id>_<rollout_id>.jsonl` for a reverted thread, with a possible `.jsonl.zst` compressed sibling. The thread id is NEVER a filename prefix.

## Acceptance criteria

- AC1 CLI: `codex-panel run --n <N> [--verify] [--out <dir>]`, diff on stdin. Exit codes are pinned: `--n` missing, non-numeric, < 2 or > 5 → exit 2 (usage on stderr) with zero vendor processes; empty stdin or > 8 MiB → exit 2, zero vendor processes; outside a git work tree → exit 2; `.vibe/review-slots` `codex=off` (or any policy failure) → exit 2, zero vendor processes; readiness failure (version floor, login probe) → exit 1 after exactly the two probe calls (`--version`, `login status`), no reviewer spawned; an incomplete panel (AC4) → exit 1; complete panel → exit 0. Total `codex` processes for a complete run are exactly 2 + N (two readiness probes, N reviewers) and the test asserts that count.
- AC2 Per-reviewer argv (k = 1..N): the ship-mode vector is EXACTLY `vibe-delegate.mjs`'s review vector as recorded from the delegate stub in the same test run (the test runs `vibe-delegate review codex` against the stub once, takes its recorded `codex exec` argv as the golden, and asserts list EQUALITY with each panel reviewer's argv — same order, same count, including the single `--ephemeral`); the verify-mode vector equals the golden with the ONE element `--ephemeral` removed and nothing else changed (ordered-list assertion: `verify == [a for a in golden if a != '--ephemeral']` AND `golden.count('--ephemeral') == 1`). The reviewers' cwds are N distinct private temp dirs outside the repo, removed afterwards; nothing is written under the repo (asserted by listing the repo before/after).
- AC3 Blind input: reviewer k receives on stdin the review instruction, a line `PANEL-NONCE: <32 hex, unique per reviewer>`, and the diff; nothing else. Nonces come from `crypto.randomBytes(16)`. Reviewers are spawned concurrently: the stub sleeps a pinned 0.5 s per call, and the test asserts every reviewer's recorded start time precedes every reviewer's recorded end time (true overlap, not sequential runs).
- AC4 Collection: each reviewer's `answer.json` is validated against the delegate's REVIEW schema AND its semantic rule (a `PASS` with any `BLOCKING` finding is invalid, as in the delegate); usage per reviewer from `turn.completed` events as in the delegate. Output on stdout: `{"n":N,"mode":"ship"|"verify","reviewers":[{"k":1,"nonce":..,"thread_id":..|null,"verdict":..,"summary":..,"findings":[..],"usage":{..}}],"tally":{"PASS":x,"FAIL":y,"SPLIT":z}}`. A reviewer that fails (non-zero exit, refusal, schema or semantic violation, missing usage) is reported as `{"k":k,"error":"..."}`, excluded from the tally, and the panel exit code is 1 (incomplete panel is never a pass); the chair decides, never this tool.
- AC5 Verify mode extras: the `thread_id` from each reviewer's `thread.started` event is recorded and its rollout is located with the LITERAL template from the task summary — glob `$CODEX_HOME/sessions/*/*/*/rollout-*-<thread_id>.jsonl` and `rollout-*-<thread_id>_*.jsonl`, and if neither exists the `.jsonl.zst` siblings (decompressed with `zstd -dc` when available, else reported as `rollout-compressed`); the file is searched for `PANEL-NONCE:` lines: it must contain reviewer k's nonce and NO other reviewer's; the result goes into `reviewers[k].nonce_check: "own-only"|"foreign-nonce-found"|"rollout-not-found"|"rollout-compressed"`, and any value other than `own-only` makes the exit code 1. The stdout JSON also carries `"retention": "rollouts kept under $CODEX_HOME/sessions"` in verify mode.
- AC6 `vs.md` § Step 5c gains a "Running under Codex" note (≤ 8 lines): the panel is `codex-panel run --n N < diff`; each panellist is a separate process; the chair still runs the correlated-agreement check on the JSON; `--verify` is the live proof, needs Martin's per-run yes, and leaves rollouts in `~/.codex/sessions`. README's Codex section gets two sentences; `docs/codex-integration-plan.md` D6 names the tool and the rollout template. The smoke test asserts the literal strings `codex-panel run --n` in `vs.md`, `codex-panel` in README, and `rollout-` in the plan's D6.
- AC7 Tests (`smoke/checks_20_codex_panel.py`, registered in `smoke/runner.py`, or appended to `checks_19` if it stays ≤ 1,500 lines): stub `codex` recording argv/stdin/env/cwd/start+end timestamps per call, sleeping 0.5 s per exec call, and, in verify scenarios, writing a fake rollout at a path the TEST constructs from the literal template (`sessions/2026/09/11/rollout-2026-09-11T12-00-00-<thread_id>.jsonl`, plus a `_<rollout_id>` variant and a `.jsonl.zst`-only variant) containing the nonces the fixture dictates (own only; own plus a sibling's; none); assertions for every AC: N processes (2 + N total), concurrency overlap, per-reviewer distinct nonces and cwds, ordered ship/verify pin against the delegate's recorded golden, every AC1 exit code with zero or exactly-two vendor calls as stated, schema and semantic failure → incomplete → exit 1, tally, all four `nonce_check` outcomes, no writes under the repo, temp dirs removed, env never forwards PATs/keys (`DO_NOT_FORWARD` pattern from `checks_17`), docs strings (AC6).
- AC8 `python3 code-check.py` clean; `python3 smoke-test.py < /dev/null` fully green.
