# task_053 — `/vs` in Codex's own terminal: leading-space pass-through plus a managed `UserPromptSubmit` hook (Martin's `y` of 2026-09-11, re-scoped; branch `astra`)

## Task summary

Martin said yes to making `/vs` work in Codex's own terminal. The route the plan offered (custom prompt files in `~/.codex/prompts`, `/prompts:<name>`) turns out to be GONE at the shipped tag: `tui/src/bottom_pane/slash_commands.rs` at `rust-v0.154.0` has only `SlashCommandItem::{Builtin, ServiceTier}` — no user prompts — and nothing under `codex-rs/` reads a `prompts/` directory, so a `vibe codex prompts` installer would write inert files (Spec Critic, 2026-09-11). What DOES exist, verified in `tui/src/bottom_pane/chat_composer/slash_input.rs:71-87` `validate_submission`: a prompt whose input STARTS WITH A SPACE (`input_starts_with_space`, `chat_composer.rs:3064`) skips slash validation; the composer then TRIMS that space (`trim_submission`, `chat_composer.rs:494, 3079-3082`) and submits `/vs …` as plain text; the managed `UserPromptSubmit` hook (allowed in a managed hooks file, `hooks/src/engine/discovery.rs:208-239`; fired for TUI input too, `core/src/hook_runtime.rs:660-684`) receives `prompt` (`hooks/src/schema.rs:566-582`) and may answer `hookSpecificOutput.additionalContext` (`schema.rs:429-448`). So the nearest honest thing: in Codex's terminal type ` /vs …` with ONE leading space (or `$vs …`, the native form); a root-owned managed hook in `/etc/codex/hooks` recognises `^\s*/(vs|vss|vsss)\b` and adds context telling the model that this is the vibe command `$<name>` and to invoke that skill with the rest of the line as arguments. Model-mediated, not deterministic — stated as such everywhere. Nothing is written to the Mac's `~/.codex`; the earlier plan wording about a `vibe codex prompts` installer is withdrawn.

## Acceptance criteria

- AC1 `devcontainer/codex-prompt-prefix.sh` (installed root-owned as `/usr/local/bin/codex-prompt-prefix`, `#!/bin/bash`, `set -euo pipefail`, fixed PATH, `unset BASH_ENV ENV`): reads the `UserPromptSubmit` JSON on stdin with `jq`, takes `.prompt`, and when the prompt's first non-whitespace token is exactly `/vs`, `/vss` or `/vsss` (case-sensitive; `/vss:foo`, `/vssx`, `/VS` do not match) prints `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"<text>"}}` where `<text>` is one sentence: `The user typed the vibe command /<name>; it is the same command as the $<name> skill. Invoke the $<name> skill now with these arguments, verbatim (they may span several lines): <everything after the token, later lines included>` (with nothing after the token → `... Invoke the $<name> skill now with no arguments.`, never a placeholder inside the verbatim field — Astra review); for any other prompt it prints nothing and exits 0; on unreadable or non-JSON stdin, a missing `jq`, or ANY failure of its own (every `jq` call guarded; the arguments travel on `jq`'s stdin, never as an argv value, so their length cannot fail the hook) it prints nothing and exits 0 (a broken hook here must never block a prompt — this hook adds context, it does not guard). ≤ 60 lines.
