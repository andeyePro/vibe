# task_052 — delegate usage ledger and `/budget` split (plan item 9, branch `astra`)

## Task summary

`/ask`, `/review`'s codex slot, `vibe-delegate role` and (later) the panel each spend tokens through `vibe-delegate.mjs`, which today reports usage per call and forgets it. Martin's decision 6 (2026-09-10) requires `/budget` to count `claude -p` calls separately from interactive use, and Astra's rationed Plus allowance needs a running total. This task makes the helper append one JSON line per call to an untracked, per-project ledger and teaches `/budget` to report the ledger as two separate lines (Astra and `claude -p`), never mixed into the interactive figures.

## Acceptance criteria

- AC1 Ledger path `<root>/.vibe/delegate-usage.jsonl` where `<root>` is the git toplevel of the INVOCATION directory (`process.cwd()`, resolved by a new NON-throwing `repoRootOrNull(process.cwd())` — never the helper's private scratch `cwd`); when the invocation directory is not inside a work tree, no ledger is written and one stderr note says so, and the call's own behaviour is unchanged (`ask haiku` outside a work tree still succeeds exactly as today; `ask astra` still refuses via `slots` exactly as today). The `<root>/.vibe/` directory is created if missing (mode 0700). The path is already excluded from git by the existing blanket `.vibe/` rule in the repo `.gitignore` and in `install-claude-extras.sh`'s managed block; the test asserts that blanket rule is present in both, and nothing new is added to either.
- AC2 One line per MODEL-INVOKING process (`codex exec` or `claude -p`; the `codex --version` and `login status` probes are not model calls and never produce a line), appended after that process returns and before stdout is written, with EXACTLY these keys: `{"ts":<ISO 8601 UTC>,"op":"ask"|"review"|"role","runtime":"codex"|"claude-p","model":<requested model>,"served_models":[...]|null,"role":<role>|null,"billing":"subscription"|"credits"|"api","usage":{...}|null,"ok":true|false,"error":<message>|null}`. `codexRole()`/`claudeRole()` gain `billing` (`"subscription"` for Astra; the resolved billing for Claude) and `served_models` (`null` for Astra; the served list for Claude) in their returned objects so the ledger and the printed JSON agree. Usage recovery on failure: `codexEvents()` is split so the parsed usage is available to the caller even when the reply validation that follows it throws (the thrown error carries `usage` as a property), and `claudeReply()` likewise attaches the parsed usage to its error; the ledger line for a failed call therefore has `"ok":false`, the error message, and NON-null usage whenever the vendor produced completion metadata (the test asserts non-null usage for a "schema-invalid reply after a completed turn" fixture and `null` for a "process exited 1" fixture). A refusal that spawned no model-invoking process appends NOTHING. No payload, no prompt text, no file names, no ids: the test asserts the exact key set above and that neither the payload literal nor `thread_id`/`session_id` appears.
- AC3 The write is append-only and atomic per line (one `write()` of one line ending `\n`); the file is created mode 0600; a ledger that is a symlink is refused (stderr note, no write, the call itself still succeeds — accounting must never block a call, but must never write through a symlink); a write error never changes the call's exit code or stdout. Astra's review (2026-09-11) tightened this: the `.vibe/` DIRECTORY must not be a symlink either; the file is opened with `O_WRONLY|O_APPEND|O_CREAT|O_NOFOLLOW|O_NONBLOCK` (no check-then-append race; a FIFO planted under the name cannot block a completed call) and `fstat` must report a regular file before the single write; the `error` field is a FIXED CATEGORY from `{process_failed, unsuccessful_turn, no_completion, invalid_usage, invalid_reply, error}`, never an exception message (a message can carry a private scratch path); and the optional `ephemeral_5m_input_tokens` sub-field is copied only when it is a non-negative safe integer, else `null`, in both the printed JSON and the ledger.
- AC4 `/budget` (`devcontainer/commands/budget.md`): a new section "Delegated calls (from `.vibe/delegate-usage.jsonl`)" instructing the lead to sum, for the current month and for today, `usage.total_tokens` per runtime — printed as two separate lines, `Astra (codex exec): <calls> calls, <tokens> tokens` and `claude -p (delegated): <calls> calls, <tokens> tokens` — plus the count of `ok:false` rows, and to state explicitly that these are NOT included in the interactive Max/Pro figures above and that the Astra line draws on the ChatGPT plan, not Anthropic's. The exact `jq` one-liner is given in the command file so every lead computes it the same way.
- AC5 `ask.md`, `review.md` and README (Codex section) each gain one sentence naming the ledger, what it records and what it never records; `docs/codex-integration-plan.md` § 3 marks item 9 delivered.
- AC6 Tests in `smoke/checks_17_delegation.py` (≤ 1,500 lines; else `checks_19`): through `_delegate_fixture`, invoked from the fixture workspace (its git toplevel): a successful `ask astra` appends exactly one line with EXACTLY the AC2 key set; `ask haiku` likewise with `runtime:"claude-p"` and a non-null `served_models`; a `role` call records `role` and a non-null `billing`; a refusal (unknown model; `codex=off`; login probe failure — where only probes ran) appends nothing; a schema-invalid reply after a completed turn appends `ok:false` with NON-null usage; a process-exit-1 failure appends `ok:false` with `usage:null`; the payload literal and `thread_id` never appear; mode 0600; `.vibe/` auto-created 0700 when absent; a symlinked ledger → no write, one stderr note, call still succeeds; invocation from outside a work tree → no ledger, one stderr note, `ask haiku` still exit 0; the blanket `.vibe/` ignore is present in `.gitignore` and the managed block; `budget.md` contains the section heading, both line templates and the `jq` one-liner; `ask.md`/`review.md`/README sentences.
- AC7 `python3 code-check.py` clean; `python3 smoke-test.py < /dev/null` fully green.
