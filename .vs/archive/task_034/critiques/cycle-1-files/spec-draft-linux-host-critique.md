# Spec Critique — Linux host support (Tier 2)

## Concerns

1. **BLOCKING — AC7/(b): watcher gate change drops `VIBE_COPY_WATCHER_FORCE`, breaking `test_vibe_path_prefix_isolation` (smoke-test.py ~3133).** That test sets only `VIBE_COPY_WATCHER_FORCE=1` (no `VIBE_COPY_CMD`) and asserts the watcher process stays alive and pollable. The spec's new gate is "Darwin **or** `VIBE_COPY_CMD` set" — FORCE-only is not in that OR, so on Linux (no `VIBE_COPY_CMD`) the watcher would now exit 0 immediately, breaking this test's `pgrep` assertions. AC19e (~2988) sets both FORCE and `VIBE_COPY_CMD` so it survives, but AC19i does not. The gate must be "Darwin or `VIBE_COPY_CMD` set or `VIBE_COPY_WATCHER_FORCE=1`" (3-way OR), or the spec must say FORCE-only tests are being intentionally rewritten — violating AC2's "no test deleted" as currently worded.

2. **BLOCKING — AC4's "golden" mechanism is unspecified and gameable.** The task brief's own question stands: if the golden is captured by running the *post-change* code (or from the current, already-edited `devcontainer.json`), the diff is tautological and proves nothing. The spec must pin the golden to a literal, checked-in pre-change fixture (e.g. embed the base `runArgs: ["--cap-add=NET_ADMIN","--cap-add=NET_RAW"]` list as it stood before this task, not re-derived from the edited file at test time). As written, a Generator could satisfy AC4's letter with a self-referential no-op test.

3. **BLOCKING — nsswitch fix has no "existing images need a rebuild" callout, despite empirical proof it's needed.** This very container's live `/etc/nsswitch.conf` already reads `mdns4_minimal [NOTFOUND=return]` **twice** — the bug is live in production images today, not hypothetical. Making the Dockerfile `sed` idempotent (AC10) only prevents recurrence in *future* builds; it does nothing for already-built images, which need a real rebuild (cache-busted, not just a layer touch, since the doubled line is already baked into a cached `RUN` layer). Neither the Changes section nor Docs/MANUAL-TESTS says this. Add a line to (d)/(e) and a rebuild note in README's Linux section.

4. **MINOR — AC4 mislabelled "Darwin invariance" when the override deliberately changes.** The override is *not* byte-identical pre/post on Darwin (the new `--add-host` line is added to everyone's base `runArgs`, Mac included) — AC4 itself concedes "but for that one line." That's a reasonable compromise, but nothing in AC or MANUAL-TESTS re-verifies real behavior on Docker Desktop/OrbStack once shipped — only the Risks section says "verify on the Mac before merge" as prose, with no test or manual-test number attached. Promote it to a MANUAL-TESTS line item (or fold into existing Mac regression testing) so it isn't just narrative.

5. **MINOR — duplicate-guard reasoning in (a) is imprecise but not wrong.** The `if flag not in cfg["runArgs"]` guard only matters if `_op_mcp_host()` ever returns literally `host.docker.internal`; for the normal case (a distinct OP hostname) the two `--add-host` strings differ and both legitimately coexist in `runArgs` — no dedup issue, no ordering issue (Docker tolerates multiple `--add-host` flags for different names). Fine as designed, but the spec's phrasing implies the guard is load-bearing for this task, when it's actually pre-existing and orthogonal. Clarify or drop the claim.

6. **MINOR — clipboard architecture is correctly diagnosed but should be stated explicitly.** Confirmed: `pbcopy` invocation (`vibe:~3847`) and `vibe-copy-watcher.sh` both run **host-side** in the launcher/watcher, never in-container (the watcher's own header even says "Runs on the Mac; no-op on Linux"). So the Linux `wl-copy`/`xclip`/`xsel` fallback must be reachable on the Linux **host's** desktop session, not inside the container — which is exactly why AC12-14 need a real Wayland/X11 session and are correctly routed to `[L]`/MANUAL-TESTS 48, not smoke tests. Worth one explicit sentence in the spec so the Generator doesn't accidentally wire the fallback into the container's shell profile.

7. **MINOR — `vibe_clipboard_cmd()` placement is right but new to the test harness.** No existing smoke test shims `uname` on `PATH`; this is new infrastructure (AC3, AC4, AC6 all depend on it). Not wrong, just flag that `_source_vibe_call` must confirm a fixture directory prepended to `PATH` actually shadows the real `uname` before the Generator relies on it silently working.

8. Everything else checks out: MANUAL-TESTS 44-50 numbering is clean (existing file ends at Test 43); `[L]` routing for AC12-14 is correct (no way to smoke-test a real Docker Engine daemon or a real display server); BSD/GNU dual-path precedent at the cited line numbers is real; `install.sh` currently has zero Linux branching, confirming (c) is greenfield; README:24/70-79 citations are accurate; `init-firewall.sh`'s `getent hosts` handling is real and already host-gateway-aware.

## Verdict

**revise** — concerns 1-3 are mechanical/correctness gaps that would either break an existing test (1), let a key acceptance criterion pass vacuously (2), or ship an incomplete fix silently (3). None require re-scoping the task; all three are one-paragraph spec additions.
