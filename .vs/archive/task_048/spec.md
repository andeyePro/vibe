# task_048 — Codex supervisor as an app-server client (plan item 6, branch `astra`)

## Task summary

The durable, failure-aware supervisor that Codex lacks (`/brain2/andeye/vibe-ChatGPT.md` § 4): `devcontainer/codex-supervisor.mjs` (installed as `/usr/local/bin/codex-supervisor`) drives ONE unattended Codex thread through `codex app-server` on stdio, so `$vsss`/`/vsss` can run under Codex across quota windows without a human turn. Facts it rests on (tag `rust-v0.154.0`, verified 2026-09-11, `scratchpad/codex-appserver.md`): newline-delimited JSON, not JSON-RPC 2.0 (`app-server-transport/src/transport/stdio.rs:42-92`, `rpc.rs:31-79`); `initialize {clientInfo, capabilities}` then usable at once; `thread/start {cwd, approvalPolicy, sandbox, config, ephemeral}` returns `thread.id`; `SandboxMode` is kebab-case and defined in `protocol/v2/shared.rs:305` (`"danger-full-access"`); `turn/start {threadId, input:[{type:"text",text}]}`; the terminal event is `turn/completed {turn.status: completed|interrupted|failed|inProgress, turn.error.codexErrorInfo}` — there is NO `turn/failed` notification; `error {error, willRetry}` is transient when `willRetry` is true; `account/rateLimits/read` and `account/rateLimits/updated` carry `RateLimitSnapshot {primary, secondary: {usedPercent, windowDurationMins, resetsAt (UNIX SECONDS)}}` with each window independently optional; `thread/resume {threadId}` needs no path and replays history, but a hard-killed turn shows `inProgress` forever, so after resume the supervisor always sends a fresh `turn/start` and never `turn/steer`; under `approvalPolicy: "never"` no approval request is ever sent, and an exec-policy-forbidden command fails the TURN (not the thread) instead of hanging; a JSON-RPC error response to `item/commandExecution/requestApproval` is handled as a graceful deny (`bespoke_event_handling.rs:2076-2156`); stdin EOF shuts the server down; `CODEX_HOME` must exist. `@openai/codex-sdk` shells to `codex exec --experimental-json` and cannot surface `codexErrorInfo` or rate limits, so it is not used. `danger-full-access` is consistent with `devcontainer/codex/requirements.toml` from task_046 (`allowed_sandbox_modes = ["read-only", "danger-full-access"]`, plan F11); the older D1 wording in the plan is corrected in task_046's close-out.

## Acceptance criteria

- AC1 CLI: `codex-supervisor run --cwd <abs workspace> --prompt-file <file> [--state <file>] [--max-turns N] [--max-resumes N] [--max-quota-waits N] [--max-transient-retries N] [--max-turn-failures N] [--max-wall-seconds N] [--model gpt-6-astra] [--codex-bin <path>] [--now-source <file>] [--new-run]`, and `codex-supervisor status --state <file>`. `--cwd` must be an absolute path inside a git work tree; the prompt file is read once; defaults: `--state <cwd>/.vss/codex-supervisor.json`, `--max-turns 50`, `--max-resumes 20`, `--max-quota-waits 12`, `--max-transient-retries 6`, `--max-turn-failures 3`, `--max-wall-seconds 36000`. Invalid arguments → exit 2, nothing spawned.
- AC2 Prefix rewrite: if the prompt's FIRST token (text before the first whitespace or end of string, case-sensitive, exact match) is `/vs`, `/vss` or `/vsss`, that token is replaced by `$vs`, `$vss` or `$vsss`; `$`-forms and every other prompt (including `/vss:foo`, `/vssx`, `/VS`) are sent unchanged. The table is exported as `REWRITES` and exercised through the CLI with a stub app-server that echoes the received `turn/start` input.
- AC3 Spawn and handshake: the supervisor spawns `<codex-bin> app-server` (argv exactly `['app-server']`, no `-c` flags, so the system requirements and managed hooks apply), with the child `env` limited to EXACTLY `PATH`, `HOME`, `CODEX_HOME` (default `$HOME/.codex`, must exist or exit 2 before spawning), `LANG` (the test asserts the recorded env keys are exactly that set); writes `{"id":1,"method":"initialize","params":{"clientInfo":{"name":"vibe-codex-supervisor","version":<vibe VERSION>},"capabilities":{}}}` as one line; refuses to proceed until the matching response arrives (timeout 30 s → exit 1 `handshake timeout`); then `account/rateLimits/read` (id 2) BEFORE any turn.
- AC4 Thread lifecycle and state: first run sends `thread/start {cwd, approvalPolicy:"never", sandbox:"danger-full-access", ephemeral:false}` and persists `{threadId, cwd, promptHash, startedAt, turns:[], resumes:0, quotaWaits:0, transientRetries:0, turnFailures:0, lastRateLimits:null, waits:[]}` to the state file ATOMICALLY (write `<state>.tmp` + rename) before the first `turn/start`. A later run with an existing state file whose `cwd` AND `promptHash` match sends `thread/resume {threadId}`, increments `resumes`, then a fresh `turn/start` regardless of the resumed turn's status (never `turn/steer`, never `thread/fork`). On every run, including a resumed one, the fresh `account/rateLimits/read` snapshot taken at start is MERGED into the adopted `lastRateLimits` field-wise per window — the persisted copy is never preferred over the fresher one (Astra re-review: a stale persisted `resetsAt` in the past would otherwise produce repeated zero-second quota waits). A state file whose `cwd` or `promptHash` does NOT match → exit 2 naming the mismatch, unless `--new-run` is passed, which first renames the old file to `codex-supervisor.<startedAt>.json` and then starts fresh. Every counter is written to the state file at the moment it changes. Resume semantics (Astra review, cycle 1): a state file that already records `exitReason` is TERMINAL — a plain `run` prints `already complete: <reason>` and exits 0 without spawning anything (`--new-run` is the way to start over); on a resumed run the first turn's input is the literal `continue` when any turn was ever STARTED — decided by a persisted `turnsStarted` counter that is incremented and written atomically immediately BEFORE each `turn/start` is sent (a turn killed mid-flight leaves `turns` empty but `turnsStarted` ≥ 1; cycle-2 Tester finding) — and the user's rewritten prompt only when `turnsStarted` is 0; if the persisted `waits[]` has a last entry whose `until` is still in the future, the supervisor honours it (sleeps until `until`, or exits 3 if that exceeds the wall ceiling) BEFORE sending anything.
- AC5 Turn loop: `turn/start {threadId, input:[{type:"text", text}]}`; read notifications until `turn/completed` for that `turnId`; `error` notifications with `willRetry: true` are logged and ignored; `item/agentMessage/delta` text is appended to `<state dir>/codex-supervisor.log`; every `account/rateLimits/updated` is merged into `lastRateLimits` FIELD-WISE per window (`primary` and `secondary` are each replaced only when present in the update). Outcome classes, by `turn.status` and `turn.error.codexErrorInfo`: (i) `completed` → record the turn, evaluate the gates (AC7); (ii) `failed` with `usageLimitExceeded` or `rateLimitExceeded` → QUOTA path (AC6); (iii) `failed` with `serverOverloaded`, `{httpConnectionFailed:{httpStatusCode:429}}`, `responseStreamConnectionFailed`, `responseStreamDisconnected` or `responseTooManyFailedAttempts` → TRANSIENT path: back off 60, 120, 240, 480, 960, 1920 s (cap 3600), `transientRetries += 1`, re-send the same turn; (iv) `failed` with `sessionBudgetExceeded` or `contextWindowExceeded` → exit 1 naming it (waiting cannot help; a fresh run with `--new-run` is the remedy); (v) `failed` with any other error (including an exec-policy `Forbidden` command, which fails only that turn) → `turnFailures += 1` and re-send until `--max-turn-failures`, then exit 1 with the last message. Retry input rule (Astra re-review): the user's rewritten prompt is sent EXACTLY ONCE per thread — for the very first `turn/start` (`turnsStarted` 0); every later `turn/start` in the same run or a resumed one, whether after a completed turn, a quota wait, a transient back-off or a turn failure, sends the literal `continue` (the thread already holds the prompt and whatever was done, so re-sending it could repeat actions); (vi) `interrupted` → exit 1 (someone else interrupted; never auto-restart). Any server→client request (`item/commandExecution/requestApproval`, `item/fileChange/requestApproval`, `item/permissions/requestApproval`, `item/tool/requestUserInput`, `mcpServer/elicitation/request`, `item/tool/call`) is answered at once with `{"id":<id>,"error":{"code":-32601,"message":"unattended"}}` and logged — it must never block (verified from source for `commandExecution`; the others are covered by the stub and the live trial in item 7).
- AC6 Quota path: from the most recent snapshot, the binding window is the one with `usedPercent >= 100` (if BOTH, the later `resetsAt`), else the later `resetsAt`; wait until `resetsAt` (unix seconds) plus 120 s grace; if no `resetsAt` is known, back off 300, 600, 1200, 2400 s (cap 3600) with a fresh `account/rateLimits/read` before each retry; `quotaWaits += 1`; each wait is appended to `waits` in the state file (`{reason, seconds, until}`) BEFORE sleeping and logged. `--now-source <file>` (unix seconds) replaces the clock for tests and makes every sleep a no-op; the computed DURATION is still written so tests can assert it. The turn is then re-sent as a fresh `turn/start` with the SAME text. Quota waits never touch `resumes`.
- AC7 Gates, checked at EVERY decision point (after a completed turn, before every quota or transient wait, before every re-send, and on resume before anything is sent): `turns.length >= max-turns`, `resumes >= max-resumes`, `quotaWaits >= max-quota-waits`, `transientRetries >= max-transient-retries`, `turnFailures >= max-turn-failures` (Astra review: the counter was missing from the gate, so restarts could bypass it; every `--max-*` value must be ≥ 1 or the CLI exits 2), or elapsed wall time (waits INCLUDED, measured from `startedAt`) `>= max-wall-seconds` → exit 3 naming the ceiling. Two more wall-clock rules from the same review: (a) while AWAITING a turn's completion the supervisor enforces the wall deadline — when it passes, it sends `turn/interrupt {threadId, turnId}`, closes the server's stdin, writes the state and exits 3 (a silent or endlessly-retrying server can never hold it forever; `--now-source` drives this in tests); the same deadline bounds every OUTSTANDING REQUEST too (`initialize`, `account/rateLimits/read`, `thread/start`, `thread/resume`, `turn/start`): a request's timeout is the smaller of its own limit and the remaining wall budget, and a request that runs out of wall budget ends the run with exit 3 naming `max-wall-seconds`, never exit 1 (Astra re-review); (b) every quota or transient wait is first capped by the remaining wall budget — if the computed wait would end after the deadline, the supervisor writes the wait it WOULD have taken to the state file and exits 3 instead of sleeping. Exit 0 when the turn's LAST completed `agentMessage` item contains, on a line of its own at line start, `VSSS-EXIT: <reason>`; the state file records `exitReason`. Otherwise the next turn is the literal one-word prompt `continue`. `status` prints the state file as a short human table and exits 0; a missing state file prints `no run` and exits 1.
- AC8 Safety: the supervisor never passes `--dangerously-bypass-approvals-and-sandbox`, never sets `-c`, never writes anything outside the state dir and the log, never reads or copies `auth.json`, never sends a prompt other than the user's (rewritten) text and the literal `continue`. On SIGTERM/SIGINT it closes the server's stdin (the server exits on EOF), writes the state file and exits 130; a second `run` with the same arguments resumes (AC4).
- AC9 Docs and the real exit contract: `devcontainer/commands/vsss.md` § "Reporting back at exit" gains the requirement that the exit report's LAST line is `VSSS-EXIT: <exit reason in a few words>` (in every runtime, so Claude-led and Codex-led runs behave the same) and a "Running under Codex" note (≤ 10 lines: the supervisor invokes `$vsss`, re-enters with `continue`, and stops on that line); the test asserts the literal `VSSS-EXIT:` is present in `vsss.md`'s exit section. README's Codex section gets one paragraph on `codex-supervisor` (exercised live only in item 7 / Test 55); `docs/codex-integration-plan.md` D7 is updated to the verified method names.
- AC10 Tests (new `smoke/checks_19_codex_supervisor.py`, registered in `smoke/runner.py`): a Python stub `codex` binary whose `app-server` mode speaks the wire format (reads NDJSON on stdin; answers `initialize`, `account/rateLimits/read`, `thread/start`, `thread/resume`, `turn/start`; plays scripted scenarios from a fixture file): normal completion with `VSSS-EXIT: done`; completion without the line, then `continue`, then the exit line; `usageLimitExceeded` with `resetsAt` = now+900 then success (wait 1020 s asserted); quota failure without `resetsAt` (back-off sequence 300/600); a transient 429 then success (60 s back-off); an exec-policy-forbidden failure then success (`turnFailures` 1, same text re-sent); `sessionBudgetExceeded` → exit 1; an `interrupted` turn → exit 1; an approval request answered with the error response without blocking; a mid-run SIGTERM followed by a second run that must send `thread/resume` + `turn/start`, never `turn/steer`; a state file with a different `promptHash` → exit 2, and with `--new-run` the old file is renamed; each ceiling → exit 3 (including a wall-clock ceiling hit during a quota wait). Assertions: exact argv, exact env key set, exact `initialize` line, prefix rewrite for `/vs`, `/vss`, `/vsss`, `$vs`, `/vss:foo`, `/VS`; state-file atomicity (no `.tmp` left); wait durations; exit codes 0/1/2/3/130; log content; no file written under `--cwd` except `.vss/codex-supervisor.{json,log}` (and the renamed archive under `--new-run`).
- AC11 `python3 code-check.py` clean; `python3 smoke-test.py < /dev/null` fully green.
