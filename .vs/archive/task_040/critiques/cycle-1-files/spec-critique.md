# Spec Critique — task_040 (cycle 1)

## Concerns

1. **AC4, BLOCKING — "source-only mode" doesn't exist as a flag.** There is no `--source-only` CLI flag. The real mechanism (used throughout `smoke/checks_02_image_drift_and_learning.py` via `_source_vibe_call` in `smoke/_core.py`) is: set env `VIBE_SOURCE_ONLY=1`, then `bash -c 'set -e; source ./vibe; <call>'`. `vibe` itself checks `[ "${VIBE_SOURCE_ONLY:-}" = "1" ] && return 0` after `parse_vibe_args` (~line 3246) to stop before the launch path. Fix wording: "Tests call `_source_vibe_call({}, 'resolve_profile ...')` from `smoke/_core.py` — same helper `checks_02` uses for `image_drift_needs_recreate`/`parse_vibe_args`. Do not invent a `--source-only` flag."

2. **AC2, BLOCKING — contradicts the repo's sha-pin lint.** `smoke/checks_12_harness_lints.py` greps every `smoke/*.py` file for a literal `git show <hex>:`/`git diff <hex>` token and fails (`check("[lint] every git show/diff <sha> literal is registered...")`) unless it's pre-registered in `HISTORICAL_PINS_ALLOWED`. If the Tester commits `git diff --name-only 6d361c2 ...` into `smoke/checks_14_profiles.py` even temporarily, `smoke-test.py` fails AC1 the same cycle. Fix: AC2's runtime form must be run as an **ad hoc shell command outside any committed test file** (Bash tool, or a throwaway local script never added to `smoke/`) — never written into `checks_14_profiles.py`. The **committed, permanent** test is only the property check already described (no `profile`/`PROFILE` token in `devcontainer/Dockerfile`; `devcontainer.json`'s `image` == `vibe-dev:latest`). Drop the "remove before close" framing — it implies the literal is committed at all, which it must never be.

3. **AC9, BLOCKING — base image has no python3, and the tool locations aren't on `node`'s PATH by default.** `devcontainer/Dockerfile`'s apt list (lines 17–41) has no `python3`, and the only `PATH` extension is `/usr/local/share/npm-global/bin` (line 91) — nothing under `~/.local/bin` or `~/.cargo/bin`, which is where `uv`'s official installer and `pipx`-installed shims land. Two fixes needed in AC9 wording: (a) add the literal apt token `python3` (or `python3-full`/`python3-venv`+`python3-pip`, spec should pick one) to the required-tokens list — don't rely on an unverified assumption that Debian's `node:20` already ships it; (b) require an explicit `ENV PATH=".../home/node/.local/bin:$PATH"` (or equivalent) in the profile Dockerfile, and a smoke assertion that `PATH` in the Dockerfile text includes `.local/bin`. Also resolve the tool question directly asked of me: prefer **`uv tool install ruff`/`uv tool install mypy`** over `pipx` — `uv`'s own installer (astral.sh, already on the allowed host list) can install `uv` itself and then use `uv tool install` for ruff/mypy, touching only pypi.org/files.pythonhosted.org/astral.sh, one fewer moving part than apt-pipx + separate uv install. If Martin still wants `pipx` on PATH as a general-purpose convenience, apt-installing it is cheap and hits no extra host — but don't require both mechanisms to install the *same* tools.

4. **AC11, MINOR — no explicit statement that a failed profile `docker build` must abort and leave no marker.** `set -euo pipefail` (line 51) already means a failing `docker build` aborts the script before any `touch` — same as the base build path — so this is likely already correct by inheritance, but the spec should say so explicitly ("profile build follows the same un-suppressed `if ...; then docker build ...; touch ...; fi` shape as the base build; a Generator wrapping the build in `|| true` or a status-capturing `if docker build ...; then` construct to print a 'friendlier' error violates this and must not land").

5. **AC7, MINOR — spell out the exact `find` prune form** so the Generator doesn't get the classic `-prune`/`-o` ordering wrong: `find "$DEVCONTAINER_DIR" -path "$DEVCONTAINER_DIR/profiles" -prune -o -type f -newer "$IMAGE_MARKER" -print`. Note the `-print` must be paired with `-type f` on the right side of `-o`, not bare, or directories rematch.

6. **AC10, MINOR — reuse `vibe_workspace_sha1`, don't reinvent hashing.** The launcher already has a two-rung `sha1sum`→`shasum` helper (`vibe_workspace_sha1`, used for the per-project Claude-history bind dir) that already handles the macOS-has-no-`sha1sum`-but-has-`shasum` case. AC10's hint-marker path should call it directly: `~/.vibe/.profile-hint-$(vibe_workspace_sha1 "$workspace")`. No collision with any existing `~/.vibe/.*` marker (only `.image-built` exists today).

7. **Item 6 verification (informational, not a concern) — confirmed sound.** `image_drift_needs_recreate "$WORKSPACE" "$IMAGE_TAG"` is called once, at line 3844, using whatever `$IMAGE_TAG` already resolved to. Since profile resolution must complete and reassign `IMAGE_TAG` to `vibe-dev:<name>` before that line, drift detection recreates the container correctly on any profile switch with **zero changes** to `image_drift_needs_recreate` itself — matches the out-of-scope boundary. Spec should say explicitly "profile resolution happens before line ~3844's drift call" so the Generator doesn't place it after and silently break this.

8. **Item 8 verification (informational) — confirmed sound.** `CONFIG_FILE` is `source`d directly (line 87), so `VIBE_PROFILE=python` in `~/.vibe/config` becomes a plain shell variable in scope for the caller to pass as `resolve_profile`'s third argument — no `export` needed, unlike `VIBE_SSH_AUTO`. No fix needed, but worth stating in the spec so the Generator doesn't add an unnecessary `export VIBE_PROFILE`.

9. **AC12, MINOR — Dockerfile context (item 4).** No `.dockerignore` exists; the base `docker build` sends all of `$DEVCONTAINER_DIR` (line 3480), which will include `profiles/` once created. Harmless (base Dockerfile has no `COPY .`), but slows the base build's context transfer as profiles accumulate. Worth one sentence in the README/AC12, not worth a test.

## Verdict

**Not ready to hand to the Generator/Tester as written — two BLOCKING items (#1, #2) will send the Tester on exactly the wrong-mechanism hunt and the Generator/Tester into a self-inflicted `smoke-test.py` failure respectively, and #3 has a real, checkable factual error (no python3, no PATH extension in base) that AC9 currently papers over with "whatever the base provides."** Fix #1–#3 before Generator starts; #4–#6, #9 are worth folding in but wouldn't block a cycle on their own. #7–#8 need no spec change, just confirm the Generator is told rather than left to discover them independently.
