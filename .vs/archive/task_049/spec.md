# task_049 — `vibe --agent codex`: a Codex-led container launch behind the liveness gate (plan item 7, branch `astra`)

## Task summary

Let the user launch a vibe container with Codex as the lead runtime instead of Claude Code, on the same container, same firewall, same mounts, same single-repo PAT, with the root-owned policy from task_046 enforced and proven before Codex starts. The launcher gains `--agent <claude|codex>` (precedence: flag > untracked `.vibe/agent` file > `VIBE_AGENT` in `~/.vibe/config` > default `claude`); a Codex launch is refused unless the Codex login mount is granted (marker + `~/.vibe/codex-allow`, task_045) — Codex without its login is useless and the refusal names both switches. Inside the container the session starts through a root-owned entry script `devcontainer/codex-entry.sh` (installed as `/usr/local/bin/codex-entry`) that runs `codex-guard-liveness`, refuses to start Codex on any failure, and otherwise `exec`s the unmodified `codex` TUI in the workspace. The auto-resume marker, stall watchdog and `claude --continue` relaunch stay Claude-only in this task (the Codex unattended path is `codex-supervisor`, item 6, invoked inside the session); a Codex launch prints one line saying so. The launch header shows `agent   : codex (policy: /etc/codex, gate: codex-guard-liveness)`. This task is the live-trial enabler: MANUAL-TESTS Test 55 gains the steps Martin runs on real Docker; nothing here makes a model call.

## Acceptance criteria

- AC1 Parsing (launcher, functions ABOVE the `VIBE_SOURCE_ONLY` guard): `_agent_resolve <flag-value> <workspace>` echoes `claude` or `codex` by the precedence flag > `<ws>/.vibe/agent` > `VIBE_AGENT` env > `claude`. The file rule, stated in full (the `.vibe/domains` idiom covers "untracked" only, so the symlink test is added here explicitly): the file is used only if `[ ! -L "$ws/.vibe/agent" ]`, `[ ! -L "$ws/.vibe" ]`, `git -C "$ws" ls-files --error-unmatch .vibe/agent` FAILS (not tracked) and `git ls-files -o -- .vibe/agent` is non-empty (positively untracked), and its first non-blank non-comment line is exactly `claude` or `codex`; any other case prints ONE `⚠ .vibe/agent ignored: <reason>` line and falls through to the next source. `parse_vibe_args` gains `--agent <value>` (the value stored in `AGENT_ARG`; `vibe --agent bogus` and `vibe --agent` with no value → the usage line + exit 1 before any Docker call; the test asserts the parser's own error path, not `_agent_resolve`'s). `.vibe/agent` joins the managed `.gitignore` block in `install-claude-extras.sh`'s `ensure_project_gitignore` and the repo `.gitignore`. `vibe --help`'s header gains one line for `--agent`.
- AC2 Gate: when the resolved agent is `codex`, the launcher requires `_codex_desired_source "$WORKSPACE"` to be non-empty; otherwise it prints `  ✗ --agent codex needs the Codex login mount: create the untracked .vibe-allow-codex marker in the project and run 'vibe codex allow' on the Mac, then relaunch` and exits 1 BEFORE image build or container creation. `VIBE_CODEX_PATH=off` therefore refuses too.
- AC3 Launch: a new `launch_codex` sibling of `launch_claude` (same `exec devcontainer exec ...` shape) runs, inside the container, `/usr/bin/env -u BASH_ENV -u ENV /bin/bash --noprofile --norc -c "exec /usr/bin/env -u BASH_ENV -u ENV PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/share/npm-global/bin SHELL=/bin/bash LC_ALL=C.UTF-8 LANG=C.UTF-8 CODEX_HOME=/home/node/.codex /usr/local/bin/codex-entry"` (Astra review: `--noprofile --norc` does not stop a non-interactive Bash from sourcing an inherited `BASH_ENV`, so both interpreters start through the absolute `env -u`, and PATH is pinned) — no model, approval, or sandbox flags on the launcher side (the system policy owns them). The entry script AUTHENTICATES the gate `--bin` names before running it: `codex-guard-liveness` must be a REGULAR file (a symlink is refused, even one to a root-owned binary) that lives in the SAME directory as the entry script's own real path (`--bin` may only name that directory), owned by the same user that owns the entry script itself and not group- or other-writable, else `codex-led session refused:` and exit 1 (Astra review and re-review: a relocation flag must never let a writable directory, or a symlink to `/usr/bin/true`, supply the thing that proves liveness; the tests therefore run a fixture COPY of the entry placed beside its stub gate). `launch_claude` is byte-for-byte unchanged and every existing `launch_claude` assertion still passes. `launch_codex` is invoked the way `launch_claude` is — BACKGROUNDED from a wrapper and waited on — so the launcher's EXIT traps (copy-watcher teardown, terminal restore) still fire: a new `launch_codex_plain` mirrors `launch_claude_supervised`'s background-and-wait shape WITHOUT the heartbeat seeding, marker refresh or stall watchdog (asserted: the function body contains `launch_codex ... &` and `wait`, and no `vibe_stall_watchdog`), stores the exit status in `CLAUDE_EXIT` (the variable the launcher's final statement already propagates), and prints one line first: `  codex-led session: auto-resume and the stall watchdog are Claude-only; run codex-supervisor inside the session for unattended work`. The existing `pkill -TERM -x claude` cleanup is left as is (it targets a leftover interactive Claude; a leftover Codex TUI is covered by the same devcontainer session ending) — no `codex` sibling is added.
- AC4 Entry script `devcontainer/codex-entry.sh` (`#!/bin/bash`, `set -euo pipefail`, `export PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/share/npm-global/bin`, `unset BASH_ENV ENV`): flags `--root <dir>` (policy root, default `/etc/codex`), `--bin <dir>` (default `/usr/local/bin`), `--login-dir <dir>` (default `/home/node/.codex`), `--` then any arguments for codex; the flags exist ONLY so tests can relocate what is looked for and they never relax what is required. (a) It refuses with exit 1 and a one-line reason if `<root>/requirements.toml` is missing, if `<login-dir>` is not a directory, or if `<bin>/codex-guard-liveness --root <root> --bin <bin>` exits non-zero (its output is passed through, then `codex-led session refused: the guard chain did not prove itself`); (b) otherwise prints `codex-led session: guard chain proven, starting codex` and `exec`s `codex` (resolved through the fixed PATH; `--codex <path>` relocates it for tests and is passed on to the liveness gate as well) with the arguments after `--`, cwd unchanged; (c) never sets `--dangerously-bypass-approvals-and-sandbox`, never passes `-c`, never touches the login dir beyond the `-d` test. Installed by the Dockerfile with `--chown=root:root` next to the task_046 scripts (and in the `chmod +x` list); `codex-guard-liveness` check (a) learns one more path, `codex-entry`, and `smoke/checks_18_codex_runtime.py`'s liveness fixture builder is updated in the same change to copy it (named here because AC8 requires a green suite).
- AC5 Header: when the agent is codex the launch banner prints `     agent   : codex (policy: /etc/codex, gate: codex-guard-liveness)` immediately after the `codex   :` mount line; when claude, nothing new is printed (the banner is unchanged for every existing test).
